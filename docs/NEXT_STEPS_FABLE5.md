# Бэклог — RSI Range Signals

Документ самодостаточен: бери задачи сверху вниз, каждая — с файлами, шагами и критериями
приёмки. Актуален на дату последнего обновления этого файла — перед началом работы свериться
с `README.md` и реальным кодом, не доверять этому списку слепо.

## Где мы сейчас (снимок)

**Бот работает вживую, полностью управляется из Telegram, 94 теста зелёные.** Это НЕ прототип —
продакшен, ведёт канал, принимает подписки. Живёт локально (launchd на Mac пользователя,
**без VPS — осознанное решение**, не предлагать деплой на сервер без явного запроса).

**Реализовано и работает:**
- Ядро SMC-стратегии: `smc_detectors.py` / `smc_setups.py` / `smc_time.py` — детекторы, сборка
  сетапов (`6226`, `1:1`, `LTF-BB/OB`, модели открытия), `SMCEngine`.
- Бэктест (`sim/backtest.py`) — walk-forward без лукахеда, лесенка TP, MFE/MAE, фандинг.
  **Честный вывод: устойчивого механического края нет** (см. `docs/chs_docs/` — вынесены из
  репозитория; там же методология и полный разбор бэктеста). Это не баг, это факт рынка/стратегии.
- Данные: `market_data.py` — ccxt с ретраями/бэкоффом, общий инстанс биржи, `run_poller`
  (выравнивание на закрытие свечи, устойчив к исключениям).
- Журнал: `journal.py` — запись, скоринг исходов **по барам** (обязательный fill лимитки,
  «стоп первым» при неоднозначности, идемпотентно), публичная статистика, когортный анализ
  (confirmed vs rejected — для полуавтомата).
- Подписка: `payments.py` — Stars (полностью авто), USDT (два режима — авто через Crypto Pay API
  или полу-ручной через ссылку+заявку), воронка free-тира, жизненный цикл (истечение,
  напоминания).
- Бот: `delivery/bot.py` — все пользовательские и админ-команды (см. README), рассылка
  через воронку, публикация в канал (сигнал + результат сделки), полная админ-панель поверх
  `runtime.py` (настройки без рестарта).
- Автозапуск: `deploy/com.rsirange.bot.plist` (launchd, `KeepAlive`, проверен на реальном краше).

**Полуавтомат (форвард-эксперимент «есть ли edge у человека») — код есть, СЕЙЧАС ВЫКЛЮЧЕН:**
`SIGNAL_MODE=auto` в проде; переключение на `semiauto` — команда `/setmode semiauto`. В этом
режиме сигналы становятся кандидатами (`/confirm`/`/reject`), журнал считает исход для обеих
когорт, `/report` показывает edge оператора. Это готовый инструмент, если пользователь захочет
его провести — не нужно ничего писать заново.

**Всё ещё заглушки (`NotImplementedError` / TODO):**
- `app/sim/paper.py` — бумажная торговля (форвард-тест + free-фича).
- `app/v2/executor.py` — авто-исполнение на ключах юзера. **Гейт: не начинать без доказанного
  edge** (полуавтомат/`/report` в плюсе на приличной выборке) — см. секцию "Чего НЕ делать".
- `app/v2/tradingview_webhook.py` — приём алертов TradingView.
- `app/repositories/*.py` — SQL сейчас живёт прямо в `journal.py`/`payments.py` (17+19 мест);
  репозитории существуют как пустые заглушки, рефактор не выполнен.

## Стратегическая рамка

1. **Не обещать доходность.** Публикуем честный журнал (канал уже это делает — постит и
   выигрыши, и стопы). Бэктест не показал края — это не секрет, это дисклеймер в каждом сигнале.
2. **Executor (реальные деньги юзеров) — под жёстким гейтом.** Не реализовывать, пока нет
   измеренного положительного edge (форвард через `/report`, если пользователь включит
   `semiauto`, либо иное доказательство на будущих данных).
3. **VPS не нужен** — бот живёт на Mac пользователя через launchd. Не предлагать деплой, если
   явно не попросят.
4. Python 3.9-совместимо (без `dataclass(slots=True)`, без `match`). После каждой задачи
   `make test` зелёный (94 теста на момент записи) + новые тесты на добавленное.

## Задачи (без строгой фазовой блокировки — приоритет условный, юзер выбирает сам)

### Продукт / рост

**Реферальная система** — «+N дней подписки за приглашённого друга».
- Файлы: `app/delivery/payments.py` (таблица `referrals` — новая миграция, поле `users.ref_by`),
  `app/delivery/bot.py` (`/start ref_<tg_id>` — deep link, начисление после первой оплаты
  приглашённого).
- Критично: начисление бонуса ТОЛЬКО после реальной оплаты (не за регистрацию) — иначе
  накрутка. Идемпотентно (один рефовый бонус на приглашённого).

**Размер позиции в сигнале** — рассчитывать qty под депозит юзера прямо в посте/личке.
- Файлы: `app/brain/risk.py` (уже есть `calculate_position`), `app/delivery/bot.py`
  (`format_channel_signal`/личный алерт — юзер один раз указывает депозит и риск% через
  `/mydeposit <сумма> <риск%>`, дальше подставляется автоматически).
- В канал (общий пост) размер не подставить — там нет депозита юзера; актуально для личных
  сигналов подписчикам.

**Триал** — N дней бесплатного полного доступа новым юзерам, авто-переход на free-тир по истечении.
- Файлы: `payments.py` (`grant_subscription` уже умеет продлевать — переиспользовать с
  `method='trial'`, но CHECK на `payments.method` сейчас разрешает только `stars`/`cryptobot` —
  либо расширить CHECK миграцией, либо (как `admin_grant`) обойтись без записи в `payments`).
  Выдавать в `/start` при первой регистрации, один раз на юзера (флаг в `users`).

**Промокоды / годовой тариф со скидкой** — код на N дней или % скидки.
- Новая таблица `promo_codes` (код, дней/скидка, лимит использований, срок действия).
  `/promo <код>` в боте.

**Живая статистика в канале** — авто-обновляемый пост (или регулярный `/post` по расписанию
вместо ручного).
- `market_data.run_poller` уже имеет `on_tick` — можно повесить туда счётчик «раз в сутки
  запости статистику» (сравнить дату последнего поста в `settings`, обновлять раз в 24ч).

### Надёжность

**Авто-бэкап SQLite.**
- `data/signals.db` — единственный источник правды (сделки, подписчики, деньги). Сейчас бэкапа
  нет вообще. Простое решение: `scripts/backup_db.py` (`sqlite3 .backup` в `data/backups/`,
  ротация N последних) + запись в `launchd` как отдельный периодический агент, ИЛИ вызов из
  `on_tick` раз в сутки. Дёшево, критично не забыть.

**TTL для зависших кандидатов** (актуально только если включат `semiauto`).
- Кандидаты без решения оператора висят вечно. Добавить в `journal.py`: кандидат старше N часов
  без confirm/reject → `expired`. Minor, не блокирует ничего в `auto`-режиме.

**Атомарность миграций** (`db.py:init_db`).
- `conn.executescript()` неявно коммитит по ходу — при падении посреди файла миграции часть DDL
  уже применена, а имя миграции не записано в `schema_migrations`. Терпимо, пока миграции простые
  и применяются к пустой/консистентной БД; чинить, если появится сложная миграция с риском
  частичного применения.

### Чистота кода (не блокирует функциональность)

**Вынести SQL в `app/repositories/*.py`.**
- Сейчас `journal.py` (17 SQL-мест) и `payments.py` (19 мест) держат SQL-строки прямо в
  бизнес-логике. Репозитории — пустые заглушки. Рефактор чисто структурный: перенести запросы,
  логику не менять. Делать аккуратно (высокий риск сломать что-то тестами не покрытое) —
  желательно одним модулем за раз с полным прогоном тестов между шагами.

### Заглушки (делать только по явному запросу, не проактивно)

**`paper.py`** — бумажная торговля. Ценность неочевидна, пока `auto`-режим уже даёт реальный
публичный трек-рекорд в канале (что paper.py и должен был заменить в дискреционном сценарии).

**`v2/tradingview_webhook.py`** — приём внешних алертов. Нет запроса от пользователя, не начинать.

**`v2/executor.py`** — см. гейт выше. **НЕ начинать без явного запроса пользователя и
без предварительного разговора о рисках** (это реальные деньги реальных людей на
неподтверждённой edge-стратегии).

## Чего НЕ делать без явного запроса

- **Не деплоить на VPS.** Пользователь прямо сказал: бот живёт локально.
- **Не подключать executor / реальные ключи бирж юзеров.** Нет доказанного края.
- **Не обещать доходность** ни в коде сообщений, ни в маркетинговых текстах — дисклеймер
  «не финансовый совет» и честная статистика уже встроены, не убирать.
- **Не докручивать пороги стратегии (`minconf`/`minimpulse`/фибо-уровни) в надежде найти
  скрытый край** — бэктест уже показал, что параметрический перебор — это подгонка под шум,
  не открытие. Если пользователь хочет искать edge всерьёз — это форвард через `semiauto` или
  новое исследование на свежих данных, не твик параметров текущей.
