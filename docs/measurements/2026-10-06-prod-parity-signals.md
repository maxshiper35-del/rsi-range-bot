# Снимок сигналов с паритетом конфига движка: находка и перепроверка (регистрация ДО прогона)

Дата: 2026-10-06.

## Находка
`data/cache5y/sig_parity` (снят 08.08) — снимок движка с включёнными `6226,1:1,LTF` и
`min_stop_pct=0`; сетапы и min_stop 1.3 отсекались потом, в портфельном слое. Но движок
выдаёт ОДНОГО кандидата на бар — с максимальной confidence ПОСЛЕ своих гейтов
(`SMCEngine.analyze_single`). Вживую гейты прода (`enabled_setups=6226,LTF`,
`min_stop_pct=1.3`) стоят в движке, поэтому бар, где 1:1 или кандидат с тесным стопом
перебивал 6226/LTF, вживую даёт сигнал 6226/LTF, а в снимке — ничего.

Сверка на BTC 1h, 5 лет (после фильтров портфельного слоя):
* sig_parity: 441 сигнал;
* движок с гейтами прода и тем же ресемплом HTF: 891 (все 441 внутри; +450: 6226 303,
  LTF-BB 135, LTF-OB 12);
* плюс старший ТФ как вживую — закрытые 4h-свечи из своего кэша, окно 199 (а не ресемпл
  200 часовых баров с частичной последней свечой): 877 (общих с sig_parity 407).

Пятый случай «замер мерил не ту конфигурацию» (см. memory backtest-parity-checklist).

## Исправление инструмента
`scripts/dump_signals.py --prod`: конфиг движка — как собирает его поллер
(`app/data/market_data.py`, из runtime), старший ТФ — ближайший из набора (как
`analyze_multi`) закрытыми свечами из его кэша, окно 199 (limit 200 минус формирующаяся).
`--set key=value` — варианты замера поверх прод-конфига. Снимок: `data/cache5y/sig_prod`
(+ `config.json` с эффективным конфигом). Сверка: `--prod` на BTC 1h = ручная эмуляция
живого пути, 877/877, 0 расхождений. Тесты: tests/test_dump_signals.py.

Не исправлено (отмечено): вживую при «углублённом» фетче (`_scoring_limit`, открытый
сигнал старше ~120ч) движок получает до 999 баров вместо 199 — замер влияния отдельно.

## Перепроверка (те же скрипты и критерии, меняется только кэш: SIG_DIR=sig_prod)
1. База: M0/M1 по половинам (`measure_entry_model`) — информационно, плюс L5/L10 против M1
   по критерию 2026-10-05-entry-model.md.
2. Пять старых решений (`measure_parity_variants`, критерий 2026-10-05-parity-recheck.md);
   V1/V4/V5 меняют гейты движка — читают свои снимки `sig_prod_setups_11`,
   `sig_prod_stop10`, `sig_prod_stop16` (`--prod --set enabled_setups=6226,1:1,LTF` /
   `min_stop_pct=1.0` / `1.6`).
3. «Только 1h» (`measure_tf_parity`, критерий 2026-10-05-tf-1h-only.md).
4. Фандинг/OI (`measure_funding_oi`, критерий 2026-10-06-funding-oi-filter.md).
5. Разбивка по сетапу × ТФ на базе (для решения о тени LTF-BB@4h — информационно).

Если решение на sig_prod меняется — предлагаем владельцу (новое значение сначала в тень,
где это возможно). Опубликованный (скрытый) бэктест пересчитывается на sig_prod только
после этой перепроверки.
