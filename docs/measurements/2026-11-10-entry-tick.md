# Замер: вход сигнала не кратен шагу цены (регистрация 2026-11-10, ДО прогона)

Записано 10.11.2026 до прогона. По истории ничего не считалось; известен один случай из прода (#874) и
правило округления executor из кода. Этот раздел после коммита не меняется; результат дописывается ниже.

## 1. Вопрос
Наблюдение главной сессии, #874 1000PEPE LONG: вход 0.0049215 стоит между шагами цены (шаг 0.000001).
Low часа — 0.004922, на полшага выше входа. Журнал касание не засчитал, цена ушла к цели без нас.

Что известно из кода до прогона:
* **Журнал** сверяет точное значение входа со свечами Bybit: `low ≤ вход ≤ high`. Цены свечей кратны
  шагу. Поэтому при входе между шагами журнал засчитывает касание, только когда цена дошла до шага ЗА
  уровнем: для подхода сверху — до нижнего соседнего шага, для подхода снизу — до верхнего.
* **Executor** ставит триггер на `price_to_precision(вход)` — ccxt округляет до БЛИЖАЙШЕГО шага BingX,
  половину — вверх. Когда ближайший шаг лежит со стороны рынка, триггер срабатывает на шаг раньше, чем
  журнал засчитывает касание.

Вопрос: как часто сигнал не исполняется по журналу из-за одного шага.

## 2. Что считаем
Только факт касания входа. Исходы сделок не считаются, правило входа не меняется.

**Данные.** 1h-сигналы обеих выборок истории — 9 монет и ротация (`research_judge.load`), решения
< 2026-08-01. Отдельно — опубликованные сигналы журнала прода (копия БД, только чтение), часовые свечи
Bybit по публичному API.

**Шаг цены** берётся из самих свечей: наибольший общий делитель цен OHLC в окне от 300 часов до сигнала
до 50 часов после. Так учитываются смены шага биржей.

**Окно касания** — как у судьи журнала: часовые бары от закрытия решающего бара, 50 часов.

**Сторона рынка** — по close решающего бара: выше входа — цена подходит сверху, ниже — снизу.

**Уровни:**
* точный вход — правило журнала;
* шаг со стороны рынка: при подходе сверху — вход, округлённый вверх; снизу — вниз;
* ближайший шаг, половина вверх — правило executor.

**Счётчики на каждой выборке:**
* сигналов; доля с входом не кратным шагу; исполнено по точному входу;
* **G — «зазор»:** по точному входу не исполнен, а шаг со стороны рынка задет. Это случай #874;
* **G_exec:** то же, но по ближайшему шагу — когда правило executor дало бы вход, а журнал нет;
* **E — раньше журнала:** исполнен по точному входу, но ближайший шаг задет на более раннем баре;
* по монетам: где G больше всего и каков шаг относительно цены.

## 3. Решение
Порог из задания главной сессии — «единицы на тысячи».
* **Закрыть одной строкой в реестре**, если G < 0.5% от числа исполненных по точному входу на обеих
  выборках истории.
* **Иначе** — описать, где это сосредоточено, и предложить регистрацию замера правила округления входа.
  Сам такой замер этим документом не запускается: исходы сделок здесь не считаются.

## 4. Исполнение
`scripts/measure_entry_tick.py`. Кэши прода только на чтение через `DATA_ROOT`. Запросы к Bybit — только
для свечей журнала прода, не чаще 2 в секунду и не в минуты такта поллера. Прод не трогается.
