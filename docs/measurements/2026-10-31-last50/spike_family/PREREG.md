# Регистрация: семейство «монета во всплеске внимания» (T10 / C48 / P30L)

Записано: 2026-10-31 13:48 CET (12:48 UTC), ДО любого прогона (паритеты тоже не запускались).
Фиксируется отдельным коммитом в локальном git-репозитории этой папки
(`test_spike_family/`); после коммита файл не меняется. Прод-репозиторий не трогается.

## 1. Гипотеза
Ротация берёт монету в вотчлист в день всплеска оборота, а бэктест-гейт оценивал её спокойные
6 месяцев до всплеска. Сигналы в такой монете (всплеск оборота, первые часы после допуска,
лонг после недельного пампа) в среднем хуже остальных. Снятие этих сигналов ДО портфельной
симуляции (освободившиеся слоты cap занимают другие сигналы) поднимает net R на сделку.
Априорное ожидание успеха низкое, ≈10–20% (доводы против: coin-age, rotating-universe,
xs-momentum, funding-oi F1). Даже при успехе это сокращение убытка, а не перевес.

Один замер, ровно три варианта. Сюда слиты turnover_spike_filter (K сдвинут с 3 на 10),
watchlist_cooloff_after_admission, pump_coin_long_veto, long_after_pump_7d,
spike_admission_rotation, chase_runup_72h, min_stop_atr_1h, young_coin_off.

## 2. Определения (t — закрытие решающего 1h-бара = `dt` сигнала + 1ч)
Бары — 1h-кэш символа той же выборки: ротация — `cache_univ`, 9 монет — `cache5y`
(пропусков в 1h-кэшах нет, проверено до регистрации; исходы не смотрелись).
k — число 1h-баров с открытием < t (последний учтённый бар закрывается в t).

* **T_K (обе стороны)**, K ∈ {5, 10, 20}; основной T10.
  - оборот бара = close × volume;
  - S0 = Σ оборота баров [k−24, k) — последние 24 часовых бара до t;
  - Sj = Σ оборота баров [k−24(j+1), k−24j), j = 1…30 — 30 предыдущих непересекающихся
    24-часовых сумм вплотную перед S0;
  - сигнал снимается, если S0 ≥ K × median(S1…S30);
  - k < 744 (история меньше 31 дня) или медиана ≤ 0 — признак не определён, сигнал проходит.
  - Отличие от `triage/coverage.py`: там блоки сдвинуты на сутки (j = 2…31, сутки
    [k−48, k−24) пропущены). Здесь — буква правила («30 предыдущих»).
* **C_H (обе стороны, только ротация)**, H ∈ {24, 48, 72}; основной C48.
  - допуск: монета есть в `membership_a` дня D и нет в списке дня D−1; повторный вход —
    новый допуск;
  - первый день списка 2024-10-24 допуском НЕ считается: списка D−1 нет, признак не
    определён (стартовый состав, а не вход по всплеску). Сколько сделок базы это затрагивает,
    будет показано справочно;
  - D* — последний день допуска с D* 00:00 UTC ≤ t; сигнал снимается, если t − D* < H часов.
  - На 9 монетах (5y) не применяется.
* **P_xL (только LONG)**, x ∈ {+0.20, +0.30, +0.50}; основной P30L.
  - c(t) — close последнего бара с открытием < t; c(t−168ч) — close последнего бара
    с открытием < t − 168ч;
  - LONG снимается, если c(t) / c(t−168ч) − 1 ≥ x; нет бара — признак не определён, сигнал
    проходит. SHORT не трогается.

Соседи: T10 → T5, T20; C48 → C24, C72; P30L → P20L, P50L.

## 3. Модель (как прод с 27.10 и замер exit-geometry)
* Только 1h-сигналы; трейл 1.5/0.2 без тейка; cap 6 на сторону; тормоз 3 стопа за 6ч;
  дедуп; ожидание касания 50ч; удержание 168ч.
* Исполнение E1m — минутный судья `scripts/measure_exit_geometry.judge_exit` (вход — бар 1h
  живого судьи, выход по минуткам Bybit `data/cache_tf/m1`, путь внутри минуты по цвету
  свечи; трейл с момента филла). Сделки с филлом < 2024-07-31 судятся на 1h и в статистику
  не входят.
* Издержки M2′: комиссия 0.055% × 2 + слип 0.15% на круг + фандинг 0.125 б.п. за целый
  час удержания (≈0.148R/сд).
* Каждый вариант — полная пересимуляция портфеля `simulate_portfolio` прода; фильтр
  применяется к списку сигналов до симуляции (по образцу measure_coin_age).
* Докачки минуток нет (окна [час филла; +170ч) всех исполнимых сигналов уже в кэше).

## 4. Паритет — до вариантов; не сошлось → стоп, вердикт «inconclusive»
1. База оригинальным путём = реплика сделка-к-сделке; 1h-паритет «только 1h»:
   3168/+169.8, 877/+59.1, 1292/−72.3, 1440/+192.7.
2. Парный E1m «реализма трейла»: −0.065 / −0.057 / −0.180 / −0.004.
3. Обвязка в 1h-режиме = база бит-в-бит (5y и ротация).
4. Минутный судья обвязки = gross R E1m замера на всех общих сделках.
5. База E1m в полной пересимуляции воспроизводит exit-geometry: W1 1026/−0.077,
   W2 872/−0.063, rot H1 1300/−0.165, rot H2 1449/−0.015 (n точно, E с округлением до 0.001;
   половины exit-geometry, без отсечки 2026-08-01 — это опубликованные числа базы).
6. Моя обвязка с пустым фильтром даёт ровно те же сделки, что база пункта 5.

## 5. Половины (по времени решения t)
* **Отбор — rot H1**: 2024-10-24 ≤ t < 2025-10-24.
* **Проверка — rot H2′**: 2025-10-24 ≤ t < 2026-08-01.
* Справочно W1 (9 монет, t < 2025-07-28, филл ≥ 2024-07-31) и W2 (t ≥ 2025-07-28,
  t < 2026-08-01) — для T10 и P30L.
* Решения ≥ 2026-08-01 у вариантов не агрегируются и не печатаются (отсечка в half_of).

## 6. Метрики на каждой половине
n; E net R/сд; ΣR net; DD (макс. просадка кумулятивного net R по времени выхода, от 0, как
`measure_trail_realism.stats`); доля снятых сделок базы (сделки базы, чей сигнал вариант
снимает, / n базы); средний net R снятых сделок базы. Сравнения — по неокруглённым числам.

## 7. Выбор (только rot H1)
Из T10, C48, P30L — вариант с максимальным E net на rot H1 при n ≥ 50% n базы на rot H1.
Соседи в выборе не участвуют.

## 8. Критерий для выбранного варианта — все пункты на rot H1 И на rot H2′
1. E(вар) − E(база) ≥ +0.03 R/сд.
2. E(вар) > p95 — `measure_one_position._p95`: 1000 случайных подвыборок без возвращения из
   net R сделок базы этой половины (порядок массива — по времени выхода, затем ключу),
   размер min(n вар, n базы), seed 0; p95 округлён функцией до 0.001.
3. DD(вар) ≤ DD(база).
4. n(вар) ≥ 50% n(база).
5. Средний net R снятых сделок базы ≤ E(база) − 0.10.

## 9. Устойчивость — все пункты на обеих половинах ротации
a) Оба соседа: E(сосед) − E(база) ≥ +0.015.
b) Без топ-5: из набора варианта и из набора базы отдельно убраны 5 лучших сделок по net R;
   ΔE ≥ +0.02.
c) Без мем-монет: из обоих наборов убраны сделки монет с `is_meme` из
   `scripts/research_aggr_clusters.py` (символ приводится к виду BASEUSDT); без
   пересимуляции; ΔE ≥ +0.02.
d) Границы порядка внутри минуты: база и вариант пересимулируются со всеми барами O→L→H→C
   и со всеми O→H→L→C; ΔE (при одинаковом порядке) > 0 в обоих случаях.

Справочно, в вердикт не входит: ΔE по сторонам (LONG/SHORT); W1/W2 для T10 и P30L; ΔE на
базе с поправкой P0 из fill_after_publication — только если её результат будет готов к
отчёту, иначе пункт помечается «не посчитан».

## 10. Решение
* Провален любой пункт 8 или 9 (или нет варианта с n ≥ 50%) — семейство закрыто,
  пороги не перебираются, заморозка не открывается.
* Все пункты пройдены — ОДИН прогон на заморозке: ротация, решения
  2026-08-01 ≤ t < 2026-10-19 (окно 19–30.10, где лежат 50 сделок, породивших гипотезу,
  исключено), база и выбранный вариант, порядок по цвету; условие ΔE ≥ 0. Затем 2–4 недели
  тени: снятые сигналы уходят в /shadow. До конца тени прод не меняется.
* В реестр: +3 варианта и +6 соседей.
