# Регистрация: «филл до постановки» — касание входа в минуте 0 / 0–1 после решения

Записано: 2026-10-31T12:47:25Z (13:47 CET), ДО любого прогона на данных (прочитан только код обвязки
и схема копии БД). После прогона файл не меняется; отступления, если будут, пишутся в отчёт.

## Правило (дословно из задания)
Сигнал недействителен — нет филла, слот cap не занимает, в статистику не входит, — если первое
касание entry по 1m пришлось на минуту 0 после решения: [t, t+60 с), где t — закрытие решающего бара
(P0). Верхняя граница — минуты 0–1, [t, t+120 с) (P01). Час филла должен открываться в t; касания в
более поздних часах не затрагиваются. В журнале прода филл засчитывается только после
executor_orders.created_at (или signal_publication.done_at), иначе статус «вход пройден до постановки».

## Регистрация до прогона (дословно из задания)
Модель и паритет базы — как в spike_family: E1m, M2′, полная пересимуляция, база exit-geometry
бит-в-бит. Половины: W1, W2, rot H1, rot H2′; решения < 2026-08-01. Заморозка не используется.

Минута касания — первая 1m-свеча с low ≤ entry ≤ high в часе филла живого судьи, если этот час
открывается в t.

Метрики на каждой половине:
- доля сделок базы с касанием в минуте 0 и в минутах 0–1;
- средний net R этих сделок в базе;
- n, E net R/сд, ΣR net и DD у базы и у вариантов P0 и P01.

Критерий (это поправка паритета, а не заявка на перевес):
(i) Существенность. Если доля P0 ≥ 1% сделок или |ΔE(P0)| ≥ 0.01R/сд хотя бы на одной половине, P0
входит в базу всех следующих 1m-замеров, а для журнала прода предлагается статус «вход пройден до
постановки». Иначе поправка касается только журнала, база бэктеста не меняется.
(ii) Механизм. Если средний net R сделок P0 ≤ E(база) − 0.30 на всех четырёх половинах, отбор против
себя подтверждён, и entry_margin_gate (k = 0.2R, соседи 0.1 и 0.3) можно регистрировать отдельно.
Иначе entry_margin_gate закрыт.
(iii) При любом ΔE вердикт о стратегии не меняется.

Сверка инструмента (проверка правила, не оценка исхода): на 1m-данных #691 и #704 обязаны попасть в
P0, #698 — только в P01. Не попали — стоп, правило определено неверно.

## Операционализация (фиксируется до прогона; критерий выше не меняет)
1. **Обвязка.** `scripts/measure_exit_geometry.py` из копии master без правок: `run_variant((data,
   ("trail", 1.5, 0.2), "color", "1m"))` — E1m (модель E, трейл 1.5/0.2 с момента филла, порядок
   внутри минуты по цвету свечи), M2′ (0.055% × 2, слип 0.15%, фандинг 0.125 б.п. за целый час),
   полная пересимуляция `simulate_portfolio` прода (cap 6/сторону, тормоз 3 стопа/6ч, дедуп, ожидание
   50ч, удержание 168ч). Данные: `rj.load("5y")` (9 монет) и `rj.load("rot")` (ротация), только 1h.
   DATA_ROOT = data прода, только чтение; докачки минуток нет.
2. **Вариант** = тот же `run_variant`, но список сигналов фильтруется ДО `rj.simulate` (подмена
   `rj.load` в процессе воркера): удаляются сигналы класса P0 (или P01). Удалённый сигнал не занимает
   слот cap, не участвует в дедупе и тормозе, сделок не даёт.
3. **Класс сигнала.** t = dt сигнала + 60 мин (решение). Час филла — `_fill_bar` обвязки (живой судья
   на 1h, ожидание 50ч, удержание 168ч). Класс считается, только если: индекс филла найден, час филла
   открывается ровно в t, t ≥ 2024-07-31 (W_START, есть минутки) и t < 2026-08-01. Минутки —
   `scripts.fetch_m1.load` (обрезка по концу 1h-кэша, как `_bars`). m = (ts первой 1m-свечи в
   [t, t+1ч) с low ≤ entry ≤ high − t) / 60 с. P0 ⇔ m = 0; P01 ⇔ m ∈ {0, 1}; P012 ⇔ m ∈ {0, 1, 2}
   (сосед, только для устойчивости). Нет минутки, касающейся входа, в этом часе — класс «нет касания
   на 1m», сигнал не удаляется (число публикуется). Отсутствует свеча минуты 0 (или 1, 2) — флаг
   «дыра», число публикуется; классификация идёт по первой имеющейся касающейся свече.
4. **Половины** по времени решения, в статистике только сделки с баром филла ≥ 2024-07-31 (как
   exit-geometry): W1 — 5y, решение < 2025-07-28; W2 — 5y, решение ≥ 2025-07-28 (1h-кэш 5y кончается
   2026-07-28, заморозки в W2 нет); rot H1 — ротация, решение < 2025-10-24; rot H2′ — ротация,
   2025-10-24 ≤ решение < 2026-08-01. Сделки с решением ≥ 2026-08-01 у вариантов не считаются и не
   печатаются; сигналы с решением ≥ 2026-08-01 не классифицируются и не удаляются (портфель причинен:
   на сделки с решением < 2026-08-01 они не влияют).
5. **Паритет базы** (до вариантов; не сошлось — стоп): прогон с пустым фильтром обязан дать таблицу
   exit-geometry бит-в-бит по n, net/сд (3 знака), ΣR (1 знак), DD (1 знак): W1 1026 / −0.077 /
   −78.9 / 113.1; W2 872 / −0.063 / −54.9 / 68.3; rot H1 1300 / −0.165 / −214.8 / 222.9; полный
   rot H2 1449 / −0.015 / −21.5 / 46.7 (последнее — только как проверка инструмента: печатается
   совпало/не совпало, rot H2′ считается отдельно). Плюс 0 сделок «nofill»/«unresolved» на минутках.
6. **Метрики.** E = средний net R на сделку (E1m, M2′), ΣR net, DD — по кумулятивному net R по времени
   выхода (`mtr.stats`). ΔE(P) = E(вариант P) − E(база) на половине. Доля P0 = (сделки базы, чей сигнал
   класса P0) / n базы на половине; аналогично P01. «Средний net R сделок P0» — по сделкам базы класса
   P0 на половине (net R из базы).
7. **Устойчивость** (описательно, вердикт по (i)–(iii) не меняет): сосед P012 (минуты 0–2); ΔE без
   топ-5 сделок (на каждой половине из базы и из варианта убираются по 5 сделок с наибольшим net R);
   без мем-монет (список MEMES из `scripts/research_aggr_clusters.py`, сравнение по базе без числового
   префикса, как `is_meme` там; сделки мем-монет убираются из статистики базы и варианта без
   пересимуляции) — доля P0, средний net R сделок P0, E и ΔE.
8. **Сверка инструмента** — до основного прогона. #691, #698, #704: symbol, entry, created_at из копии
   БД прода (только чтение); t = created_at + 1ч. Минутки этих часов в кэше прода
   `data/cache_tf/m1` отсутствуют, берутся из кэша Bybit public kline соседнего агента
   `last50/ds_agent/cache/m1` (только чтение); если и там нет — докачка ≤ 2 запр/с только этих часов.
   Та же функция классификации, что в основном прогоне.
9. **Живые задержки** (описательно, без критерия): по копии БД — задержка executor_orders.created_at и
   signal_publication.done_at от закрытия бара; сделки журнала, где filled_at < executor_orders.created_at
   (кандидаты в статус «вход пройден до постановки»), их число и R.
10. **Заморозка 2026-08-01 … 2026-10-30 не используется** (см. регистрацию). entry_margin_gate в этом
    замере не прогоняется — по (ii) только решается, открывать ли ему отдельную регистрацию.
11. Процессы: `nice -n 15`, не больше 4.
