## A. Подтверждение исполнения лимитки — ДЕЛАЕМ (приоритет 1)

Нет ни статуса `filled`, ни `filled_at`, ни уведомления: fill — локальная переменная в
`journal._outcome_from_bars`, пересчитывается каждый тик. План:
- миграция `009_filled_at.sql`: `signals.filled_at TEXT` (статус-CHECK не трогаем — `open`
  остаётся, fill фиксирует колонка; перестройка CHECK в SQLite не стоит свеч);
- `update_outcomes_from_bars` при первом обнаружении касания entry персистит `filled_at`
  (dt бара) и возвращает запись `{"status": "filled", ...}` в общем списке;
- бот постит в канал «🎯 Вход исполнен» только для свежих филлов (не старее ~2 баров ТФ) —
  чтобы после деплоя не выплюнуть задним числом филлы по старым открытым сигналам;
- **бонус к честности**: `expired` (лимитка не исполнилась за 50 баров) сейчас молчит —
  добавляем пост «⌛ отменён, сделки не было», подписчик отличает «ждём» от «отменён».

## B. Результат с учётом плеча — ДЕЛАЕМ с поправкой (приоритет 1)

Реального плеча в данных нет и быть не может (бот не исполняет сделки). Честная замена:
- журнал отдаёт в `closed`-словаре `entry`, `exit_price`, `price_move_pct`;
- пост результата: ведущим числом `При плече ×N: +X%`, вторым — сырое движение цены,
  R-мультипликатор остаётся (валюта трек-рекорда);
- `N` — новая runtime-настройка `display_leverage` (дефолт 10, 0 = строка выключена,
  правится из админки без рестарта).

## C. Единый HTML-рендерер сообщений — ДЕЛАЕМ (приоритет 1)

Сейчас parse_mode нигде не задан (всё plain text), шаблонов сигнала ДВА и они разошлись
(канальный в bot.py и DM в signal_engine.py). План:
- новый модуль `app/delivery/templates.py`: escape всех динамических строк, `<b>/<code>/<i>`,
  «Почему» — в `<blockquote expandable>` (Bot API 7.3+, проверить версию aiogram);
- через него: сигнал-канал, сигнал-DM, тизер, candidate-alert, fill, expired, результат;
- заодно фикс найденного бага: `_broadcast` выбирает шаблон по `cfg.signal_mode` (.env),
  а не `runtime.signal_mode()` — смена режима из админки не меняла тело рассылки;
- выкладка: сначала живой прогон рендера в DM админу реальным ботом, потом включение.

## D. График с зонами входа/стопа/тейков — ДЕЛАЕМ (приоритет 2)

mplfinance не берём (эстетика отвергнута). Свой SVG-рендер свечей в `graphics.py` в стиле
уже принятой «bold»-карточки недели: свечи + полупрозрачная красная зона entry↔stop, зелёная
entry↔TP, подписи, вотермарк @rsi_range. Данные — `fetch_closed_ohlcv(symbol, tf, ~60)`
(публичная, кэш ccxt-инстанса, ретраи). Фича-флаг `signal_chart_enabled` (дефолт off):
проверка в DM админа → включение; пост сигнала становится `send_photo` с подписью из C.

## F. Мультитаймфрейм — ГЕЙТ: только через бэктест (приоритет 3)

Скан УЖЕ конфигурируемый (1h+4h), но: «30m» отсутствует в `_TF_SECONDS` (тихо фильтруется);
движок выдаёт максимум один сигнал на символ с ОДНОГО entry-TF; бэктест гоняет один ТФ без
HTF-контекста; у `scripts/run_backtest.py` нет CLI-аргументов. План: добавить CLI
(symbol/tf/limit), прогнать 15m/30m/1h/4h × BTC/ETH/SOL для включённых сетапов, решение по
цифрам. Включение ТФ — конфигом (уже так).
