# Аудит безопасности RSI Range (@rsirange_bot) — 30.10.2026

**Скоуп:** обработка апдейтов Telegram (админ-гейты, callback_data, FSM, inline, пересылки),
Mini App (Flask + waitress за quick-tunnel Cloudflare), платежи (Stars, CryptoBot USDT,
промокоды, рефералка, возвраты), executor BingX (демо), хранение секретов и бэкапов,
логи, зависимости, launchd/туннель, rate limiting, GDPR.

**Метод:** статический разбор кода (`app/`, `scripts/`, `deploy/`, `migrations/`), локальные
тесты и замеры в изолированном worktree. Прод не трогался: ни одного сообщения в Telegram,
ни одного приватного вызова биржи, ни одной записи в боевую БД. Содержимое `.env` не
читалось — только права файла, имена переменных и признак «пусто/не пусто». Из бэкапа
(не из живой БД, `mode=ro&immutable=1`) прочитаны только ИМЕНА ключей `settings` и число
строк с `api_key_enc` — без значений.

«Лонг или шорт?», правки напоминаний и free-квоты); влитый код тоже разобран (см. ниже).

Главное:
1. **H-1 (исправлено).** Любой юзер пересылкой одного поста замораживал ВЕСЬ бот на ~5 с
   (ReDoS в разборе пересланного сигнала, синхронно на event loop, до лимита 20/сутки).
2. **H-2 (исправлено).** Любой подписчик — и любой новичок на бесплатном 5-дневном триале —
   подделкой `callback_data` (`sigcalc:<id>`) получал вход/стоп/тейки и карту теневых
   сделок и кандидатов semiauto.
3. **M-1.** Спам кнопкой «💵 USDT» ломает авто-активацию USDT-оплат для всех.
4. **M-2.** Inline-режим без троттлинга: любой может забить общий лимитер биржи, который
   делит с поллером сигналов.
5. **M-4.** Тесты подтягивают боевой `.env` и (из основного чекаута, т.е. в pre-commit)
   читают боевую `data/signals.db` — латентный риск записи в прод при каждом коммите.

## Детали исправленного

### H-1 — ReDoS в проверке пересланных сигналов (`905d3e7`)

Замер на текущем Mac (один вызов `parse_signal`, вход ~4 КБ):

| Вход | До | После |
|---|---|---|
| 4 КБ цифр в строке стопа | 5497 мс | 5.7 мс |
| 4 КБ цифр строкой-значением | 5334 мс | 6.6 мс |
| 4 КБ цифр во входе | 4777 мс | 5.5 мс |
| пробелы после `coin` | 2246 мс | 2.0 мс |
| пробелы после тикера (`_PAIR`) | 1688 мс | 2.3 мс |
| пробелы после ключевого слова (`_INDEX`) | 581 мс | 5.5 мс |
| пробелы после числа (`_VALUE_LINE`) | 348 мс | 3.9 мс |
| 12 КБ текста (сверх лимита Telegram) | — | 5.5 мс (обрезка до 4096) |

Почему это High, а не Medium: разбор шёл прямо в корутине хэндлера — пока считается regex,
не исполняется ни одна задача asyncio (поллер, стрим филлов, обслуживание с платежами,
ответы всем юзерам). Пересылку может сделать любой, кто открыл бота; лимит «20 проверок в
сутки» стоял ПОСЛЕ разбора и считал только распознанные сигналы.

Эквивалентность: правки только переставляют квантификаторы (`\s*-?\s*` ≡ `(?:\s*-)?\s*`) и
запрещают старт числа внутри серии цифр (совпадение с середины серии существует тогда и
только тогда, когда существует с её начала, а re.sub берёт самое левое). Подтверждено
дифференциальным фаззингом: 60 000 случайных текстов из токенов сигналов и «мусорных»
символов (сравнение `parse_signal`, `_nums`, `_coin`, `_VALUE_LINE`, `_INDEX`) + 30 000
реалистичных постов разных форматов (10 937 распознаны) — 0 расхождений. Закреплённые в
тесте крайние случаи проверены и на старом коде.

### H-2 — тени и кандидаты по поддельному callback (`b72453d`)

Цепочка: новый юзер `/start` → триал 5 дней (`is_paid` = True) → юзербот вызывает
`messages.getBotCallbackAnswer(peer=@rsirange_bot, msg_id=<любое сообщение бота с
инлайн-кнопками>, data=b"sigcalc:<N>")` для N из пропусков в нумерации канала → бот отвечает
`/calc … <вход> <стоп>` для теневой сделки; `sigchart:<N>` присылает PNG с входом, стопом и
тейками. Тени создаются постоянно (гейт «вход уже пройден» = `entry` и тень `LTF-BB@4h` по
умолчанию), открытые тени — это живые непубликуемые сделки.

Фикс не трогает права (подписка/доставлен полный сигнал), а добавляет фильтр статуса с той же
границей, что у публичного CSV. Тест сверяет `public_signal_row` с `export_public_trades`,
чтобы границы не разошлись в будущем.
