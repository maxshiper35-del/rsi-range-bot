# Что ставить для видео с Claude Code на этом Mac

**Коротко:** нужен один движок — **HyperFrames**. Его ставим в отдельную папку и закрепляем версию. **Three.js** отдельно не ставится: это библиотека, её подключаем внутри HyperFrames для 3D-интро. **Remotion** сейчас не ставим, он останется запасным вариантом. **Blender** не ставим. Всё бесплатно и займёт около 0,35 ГБ. Python-часть (данные, тексты, проверки, звук) не меняется. Я ничего не устанавливал.

| Утилита | GitHub | Звёзды / лицензия / версия | Решение |
|---|---|---|---|
| HyperFrames | https://github.com/heygen-com/hyperframes | 76,5 тыс., Apache-2.0, 0.8.224 (31.10) | **ставить** |
| Three.js | https://github.com/mrdoob/three.js | 117 тыс., MIT, r187 = npm 0.187.0 (30.10) | **как npm-пакет внутри HyperFrames** |
| Remotion | https://github.com/remotion-dev/remotion | 69 тыс., Remotion License, 4.0.539 (26.10) | не сейчас, запасной вариант |
| Blender | https://github.com/blender/blender (зеркало; разработка на projects.blender.org) | 21,5 тыс., GPL, 4.5.15 LTS — последняя версия для Intel | не ставить |

## 1. Рекомендуемый стек, по порядку

0. **Уже есть и остаётся:** `.venv` бота, Playwright, ffmpeg 8.1.2, Node 24.14.
1. **HyperFrames 0.8.224** в `~/video-lab`, вне репозитория бота. Ролик в нём — одна HTML-страница с таймлайном GSAP. Программа проматывает её по кадрам (30 в секунду), снимает в безоконном Chrome и собирает MP4 через ffmpeg.
2. **Навыки HyperFrames для Claude Code**, чтобы Claude писал ролики по правилам движка.
3. **Локальные копии three.js и GSAP** в той же папке — когда дойдём до 3D.

**Почему HyperFrames, а не Remotion.** Исследование советовало ставить оба, но они делают одно и то же.
- **Тот же принцип, что у нас сейчас:** HTML/CSS/SVG → Chrome → ffmpeg. Наши готовые куски почти без изменений переезжают в HyperFrames: `BASE_CSS`, `_CSS`, `end_card`, `frame_svg`, `equity_svg`. Для Remotion их пришлось бы переписать на React/TypeScript — это второй набор инструментов рядом с Python.
- **Уже проверен на этом Mac.** С 18.07 стоит старая версия 0.7.61. Пример `/Users/mac/Downloads/hf-project-video01` (вертикальный, 29 с) отрендерился примерно за 1–1,5 минуты.
- **Лицензия Apache-2.0** без ограничений по числу людей. Remotion бесплатен только частным лицам и командам до 3 человек, а в версии 5.0 его условия поменяются.
- **Поддержка three.js встроена.** Флаг `--browser-gpu` останавливает рендер с ошибкой, если видеокарта недоступна. Иначе 3D молча считалось бы на процессоре рядом с ботом.
- **Легче:** около 0,35 ГБ против примерно 0,5 ГБ на каждый проект Remotion.

**Минусы, честно.**
- Проекту 7,5 месяца, версии ещё 0.x, на npm 576 версий и новая почти каждый день. Версию закрепляем и обновляем только вручную.
- Отправка статистики разработчику (телеметрия) по умолчанию включена — её выключаем.
- Сами авторы на своей странице признают, что Remotion зрелее, а ролик в HyperFrames «тихо ломается», если нарушить правило «каждый кадр зависит только от времени»: https://hyperframes.heygen.com/guides/hyperframes-vs-remotion.md

## 2. Команды установки и объёмы

```bash
mkdir -p ~/video-lab && cd ~/video-lab && npm init -y
npm i -D -E hyperframes@0.8.224     # пакет 23,7 МБ; с зависимостями ~100 МБ (оценка)
npx hyperframes telemetry disable   # выключает телеметрию и тестовые раскатки новых версий
npx hyperframes browser ensure      # Chrome без окна для mac-x64, ~200 МБ
npx hyperframes doctor --json       # смотреть поле "ok": команда всегда завершается кодом 0
npx hyperframes skills update       # навыки для Claude Code, ~3,5 МБ, для пользователя
# к 3D-пилоту — версии, под которые написан блок extruded-logo:
npm i -E three@0.184.0 gsap@3.14.2  # 37 МБ + 6 МБ, без зависимостей
```

- **Вместо навыков можно поставить плагин:** `claude plugin marketplace add heygen-com/hyperframes && claude plugin install hyperframes@hyperframes`. Он клонирует репозиторий примерно на 328 МБ, вызывается командой `/hyperframes:hyperframes`.
- **Уборка, по желанию:**
  - удалить старую версию командой `npm uninstall -g hyperframes`, чтобы `hyperframes` в терминале не запускал 0.7.61;
  - после проверки удалить старый Chrome 152.0.7928.2 из `~/.cache/hyperframes/chrome` (~200 МБ).
- **Итого:** около 0,35 ГБ на диске, скачать нужно 0,2–0,3 ГБ, стоимость 0 €. Свободно 42 ГБ.
- **Three.js** — npm-пакет без зависимостей. Claude достаточно дать ссылку https://threejs.org/docs/llms.txt: там актуальные правила API, без устаревших приёмов.
- **В одном проекте — одна версия three.js.** Блок `extruded-logo` берёт three 0.184.0 и GSAP 3.14.2 из интернета (jsDelivr). Для боевой работы эти файлы кладём в папку `vendor/` проекта и меняем ссылки на локальные.

## 3. Что чем делаем в наших роликах

**HyperFrames + GSAP — основная 2D-часть**
- **Повтор реальной сделки.** Функция `replay_plan()` в `/Users/mac/bot ctypto/app/delivery/replay.py` уже считает всё нужное: свечи, вход, путь стопа при трейле, выход, итог в R. Python пишет её результат в `data.json`.
  - Отрисовку графика `frame_svg` (около 115 строк) переносим на JS почти построчно: она рисует кадр для любого момента времени.
  - Свечи плавно вырастают одна за другой, линия входа прорисовывается, стоп сдвигается при трейле, тейки подсвечиваются.
  - Сейчас повтор — это до 72 отдельных кадров по 0,11 с. Станет плавной анимацией на 30 кадров в секунду.
- **Счётчики.** «+1,8R» или «10 000 $ → 10 840 $» докручиваются готовыми блоками `number-wheel` или `slot-machine-roll`, либо анимацией GSAP с цифрами одинаковой ширины. Сейчас такой счётчик — 12 скриншотов по 0,1 с.
- **Кривая доходности за неделю** прорисовывается линией: свой SVG или готовый блок `mk-line-graph`.
- **Подписи на русском** — обычный HTML поверх видео. Заголовки с анимацией, подсветка по словам (`caption-highlight`), тайминги задаёт Python. Озвучки у нас нет, поэтому распознавание речи не нужно.
- **Переходы:** `whip-pan`, `light-leak`, `flash-through-white`.

**Three.js внутри HyperFrames — только 2–4-секундный «крючок» в начале**
- **3D-логотип:** блок `extruded-logo`, объёмное «RSI» в хроме или золоте. Блок понимает только латиницу и до 8 символов, «RSI» подходит. Его надо переделать с горизонтального кадра 1920×1080 на вертикальный.
- **3D-монета:** цилиндр с фаской, знак ₿ из нашего SVG, вращение и падение.
- **«Город свечей»** для ролика «Обвал за 60 секунд»: объёмные свечи из реальных цен (кэш `data/cache/crash`), пролёт камеры, свечение.
- **«Искры» ликвидаций** — частицы с фиксированным зерном случайности (блоки `confetti`, `particle-text-dissolve`).
- **Весь текст остаётся в HTML поверх 3D.** Тогда его видят наши проверки `check_public`/`visible_text`, и не возникает проблем с кириллицей внутри 3D.

**Python и ffmpeg — остаются как есть:** журнал и свечи, тексты, `check_public`, `.txt` с подписью для публикации, своя музыка `soundtrack.build`, выравнивание громкости и сведение со звуком, публикация на YouTube.

## 4. Что не ставим и почему

- **Blender.**
  - На Intel-Mac потолок — версия 4.5.15 LTS, поддержка примерно до июля 2027. Версии 5.x выходят только для Apple Silicon.
  - Фотореалистичный рендер Cycles на видеокартах AMD и Intel в Mac убрали в версии 4.3. Остаётся процессор: 15–60 с на кадр, то есть часы полной загрузки рядом с ботом.
  - Про быстрый движок EEVEE в баг-трекере Blender есть жалобы на зависания на Intel-маках, в том числе с Radeon 5500M, как у нас.
  - Официальный MCP-сервер Blender и коннектор Anthropic требуют Blender 5.1+, то есть тоже только Apple Silicon.
  - Наши ролики — 2D-графики и русский текст, а это как раз слабое место Blender. 3D-интро закрывает three.js на видеокарте: около 0,15 с на кадр.
  - Вернуться к нему стоит ради фотореалистичной обложки или после перехода на Apple Silicon.
- **MCP-мосты для Blender.**
  - mcp-for-blender открывает на компьютере порт 9876 без пароля, выполняет любой Python и по умолчанию отправляет статистику.
  - У fnf-blender-mcp нет открытого кода, пакету полтора месяца.
  - В инструкции пресета Higgsfield /use-blender написано: «The command itself authorizes these setup steps» (то есть сама команда якобы разрешает установку). Это текст сервиса, а не разрешение владельца, по нему ничего не ставилось. Ставить ли — решение владельца.
- **Remotion — не сейчас.** Он делает то же, что HyperFrames, но требует React/TypeScript (~0,5 ГБ и около 350 пакетов на проект) и переписывания шаблонов. Скоро выйдет 5.0 с несовместимыми изменениями и новыми условиями лицензии. Это запасной план, если пилот HyperFrames провалится: Remotion развивается 5 лет, и у него есть официальный плагин для Claude Code.
- **React Three Fiber и @remotion/three** нужны только вместе с Remotion.
- **Theatre.js** заброшен: публичных коммитов нет с 14.08.2024. Это редактор для работы мышью, Claude им не управляет.
- **Сторонние навыки и MCP для three.js** не нужны, хватает официального llms.txt.
- **Облачный HyperFrames MCP** (`compose`, `render_video`) не годится для ежедневных роликов. Он платный (кредиты HeyGen), каждый раз даёт другой дизайн, может вставить «демо» или внутренние названия сетапов и не видит наших данных и шрифтов. Для разового промо — только если владелец решит потратить кредиты.
- **Медиа-MCP** (`generate_video`, `scene_builder_3d`) тратит кредиты, для роликов на реальных данных не нужен.
- **Модели речи** Parakeet (640 МБ), Whisper, Kokoro не нужны: озвучки нет, а Kokoro не умеет по-русски.
- **60 кадров в секунду и 4K** для Shorts не нужны, а рендер идёт в 2–4 раза дольше.

**Про Intel и бота на этом же Mac.** macOS 26 — последняя версия для Intel, но Chrome и HyperFrames для Intel пока выходят. Ролик в HyperFrames — обычный HTML-проект: он отрендерится и на Apple Silicon, и на Linux, а проект Blender 4.5 так легко не переедет. Рядом с ботом рендерить так:
- с пониженным приоритетом `nice -n 15`;
- с `--workers 1`: один Chrome примерно на 256 МБ, кадры сразу уходят в ffmpeg без временных файлов;
- с `--browser-gpu` для 3D;
- не в окно HH:58–HH:03 UTC, когда бот шлёт сигнал.

Без `--workers 1` на macOS параллельный захват пишет сырые кадры на диск — по документации около 25 ГБ на минуту видео. Шейдерные переходы тоже пишут кадры на диск даже с одним процессом.

## 5. Лицензии

- **HyperFrames — Apache-2.0.** Бесплатно, можно коммерчески, без ограничений по числу людей, локальный рендер без аккаунта. Платное только облако HeyGen: `compose`, `render_video`, `cloud render`, голоса, музыка. Команду `hyperframes publish` (выкладывает проект в их облако) не использовать.
- **GSAP** — «Standard No Charge License»: https://gsap.com/standard-license. Бесплатно и для коммерции. Запрещено встраивать его в конструкторы анимации без кода, которые конкурируют с Webflow; наш случай под запрет не попадает. Это не классическая открытая лицензия.
- **Three.js — MIT.** Шрифт Geist в 3D-логотипе — свободная лицензия OFL. Наши RR Sans (это Inter) и RR Mono (IBM Plex Mono) тоже под OFL и уже лежат в `app/delivery/assets/fonts`.
- **Системный шрифт.** Сейчас шортсы набраны системным шрифтом Apple (`-apple-system`, SF Pro). Для коммерческих роликов это серая зона лицензии Apple. HyperFrames всё равно требует подключать шрифт явно, поэтому в новых роликах — RR Sans с кириллицей.
- **Музыка своя** (`soundtrack.build`), чужих прав нет. Каталог музыки HeyGen не брать.
- **Если когда-нибудь Remotion** — владельцу как частному лицу бесплатно: https://github.com/remotion-dev/remotion/blob/main/LICENSE.md.
- **Blender — GPL**, но отрендеренные ролики принадлежат нам.

## 6. Пилот: «Повтор сделки 2.0», 18 с, вертикальный 1080×1920, 30 кадров в секунду

Берём закрытую сделку из журнала, для которой в паке уже есть старый повтор, и сравниваем два ролика рядом.

**Сценарий**
- **0–2,5 с** — 3D-логотип «RSI» в золоте (three.js на видеокарте). Поверх HTML-заголовок «Повтор сделки: BTC, лонг».
- **2,5–12,5 с** — плавный повтор свечей по `replay_plan()`.
- **12,5–15,5 с** — счётчик R докручивается до итога: зелёный или красный, как было на самом деле.
- **15,5–18 с** — финал: «расчёт по журналу, до комиссий», «Не финансовый совет», @rsi_range. Без «демо» и без «реальной сделки».
- **Звук** — наш `soundtrack.build`: щелчок на входе, аккорд на итоге.

**Шаги**
1. Установка по пункту 2.
2. Скрипт вне прода запускается через `.venv/bin/python`. Он берёт строку из журнала (база только на чтение), пишет `data.json` и прогоняет все тексты через `check_public`.
3. Claude собирает ролик с навыком `/hyperframes`. GSAP, three.js и шрифты лежат в `vendor/` проекта.
4. Проверки: `npx hyperframes lint` и `npx hyperframes check --strict --at 1,5,10,14,17 --snapshots`. Они ловят текст за краем кадра и плохой контраст. Кириллицу проверить глазами по снимкам.
5. Рендер:
   ```bash
   HYPERFRAMES_NO_UPDATE_CHECK=1 HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1 \
   nice -n 15 ~/video-lab/node_modules/.bin/hyperframes render ~/video-lab/pilot-replay \
     --workers 1 --browser-gpu --output ~/video-lab/out/pilot.mp4
   ```
   Потом добавить звук той же склейкой ffmpeg, что в `frames_to_mp4`.

**Пилот прошёл, если:**
- 18 секунд рендерятся не дольше 3 минут. Жду 1–3 минуты, но это оценка, нужен замер.
- `--browser-gpu` не падает (3D считает видеокарта), и рендер не забивает все ядра.
- Временные файлы меньше 1 ГБ. Шейдерных переходов в пилоте нет.
- Два рендера подряд дают одинаковые кадры в контрольных точках.
- В проекте нет внешних ссылок: `grep -rn "https://"` ничего не находит. Сеть для проверки не выключать — на маке работает бот.
- Рендер работает в урезанном окружении, как у бота под launchd: `env -i HOME=$HOME PATH=/usr/local/bin:/usr/bin:/bin …` с абсолютными путями. Если видеокарта под launchd недоступна, `--browser-gpu` упадёт — тогда рендерим без 3D-вставки.
- Владелец смотрит старый и новый повтор рядом и решает, стало ли круче.

Если пилот провалится, остаётся старый конвейер, а тот же пилот пробуем на Remotion.

## 7. Как это встраивается в текущие скрипты

HyperFrames заменяет **один шаг**: «список (HTML, длительность) → MP4 без звука». Сейчас это `page.set_content` + скриншот + склейка в `frames_to_mp4`. Остальное остаётся:

- **Данные и тексты — в Python.** `replay_plan`, `week_stats`, журнал, свечи. `check_public` по всем строкам до рендера, как сейчас; `Caption` → `.txt` для публикации.
- **Шаблон на каждый формат** — папка с `index.html` и `vendor/`.
  - Python копирует её во временную папку, пишет `data.json` и сам ставит общую длительность ролика по числу свечей или сделок. Переменные шаблона длительность ролика менять не могут.
  - Наши `BASE_CSS`, строка бренда, финальная карточка и SVG-графики переезжают почти без изменений.
  - Логика `Timeline` и `ease_out` превращается в таймлайн GSAP, а отрисовка по времени (как `frame_svg`) — в `registerFrameSource`.
- **Рендер через `subprocess`.** Указывать абсолютный путь к программе и `PATH=/usr/local/bin:/usr/bin:/bin`: под launchd иначе не найдутся node и ffmpeg, как было с ffmpeg 27.10. Плюс три переменные из пилота, `nice -n 15`, `--workers 1`, а `--browser-gpu` — только для 3D.
- **Звук.** Вторую половину `frames_to_mp4` вынести в отдельную функцию `mux_soundtrack(video, total, seed, cues)`. Ей будут пользоваться оба движка; моменты звуковых акцентов Python считает, как сейчас.
- **Превью.** `hyperframes snapshot --at …` заменяет `kit.snapshot` для `--preview`, а `check --strict` — ещё одна проверка перед рендером.
- **Запасной путь.** Новый движок включать флагом по одному формату, например `VIDEO_ENGINE=hf` для повтора сделки. При любой ошибке HyperFrames откатываться на старый `frames_to_mp4`, чтобы ежедневный пак не ломался.
- **Остальные форматы** — квизы, дневник, «Обвал за 60 с», итог недели — пока работают на старом конвейере и переезжают по одному после пилота. Первыми — «Обвал» и итог недели: там ступенчатая анимация заметнее всего. Playwright и старые скрипты не удаляем.
